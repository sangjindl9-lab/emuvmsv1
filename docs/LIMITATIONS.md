# 알려진 제한사항 (Known Limitations)

이 문서는 EUMBMS 2.0.0 빌드에서 **구현되지 않았거나 검증되지 않은** 항목을 사실대로 기록합니다.
“구현 완료”와 “실장비 검증”을 혼동하지 않도록, 아래 항목은 화면·문서에서도 완료로 표시하지 않습니다.

## 1. 통신·프로토콜

1. **실장비 통신 검증 0건**: 이 빌드에는 실제 제조사 PLC·RTU·계량기와의 현장 통신 검증 결과가 없습니다.
   Modbus 계열은 실제 TCP 소켓 기반 시뮬레이터로만 검증했습니다.
2. **로컬 RS-485/RS-232 직접 구동 미지원**: 시리얼 포트를 직접 여는 네이티브 드라이버를 포함하지 않았습니다.
   지원 범위는 **시리얼-이더넷 변환기 경유 Modbus RTU/ASCII over TCP**입니다(게이트웨이/변환기 필요).
3. **대부분의 비-Modbus 프로토콜은 문서 확인 단계**: BACnet/IP, OPC UA, MQTT, DLMS/COSEM, M-Bus, IEC 61850, IEC 60870-5-104, DNP3, SNMP, S7, MC, XGT FEnet, FINS, EtherNet/IP, ADS는 카탈로그/문서 확인만 되어 있고 실제 드라이버가 없습니다.
4. **제조사 전용 프레임의 보편 해석 불가**: 사용자 정의 프레임 편집기는 TCP 전송과 일반적인 Header/CRC/고정 오프셋 파싱을 지원하지만, 암호화·세션 협상·동적 태그 검색이 필요한 프로토콜은 별도 드라이버가 필요합니다.
5. **UDP·시리얼 전송의 사용자 정의 프레임 미지원**: 현재 방식 ③은 TCP만 지원합니다.
6. **Modbus Security(TLS) 미구현**: 문서만 등록되어 있습니다.

## 2. 프로토콜 자동등록(방식 ②)

1. **스캔 이미지 PDF OCR 미지원**: 텍스트 레이어가 없는 PDF는 추출되지 않습니다.
2. **CID 폰트로 인코딩된 한글 PDF**는 텍스트가 깨지거나 추출되지 않을 수 있습니다.
3. **암호가 걸린 PDF/ZIP**은 열지 않습니다.
4. **XLSX는 첫 워크시트 중심**이며, 수식은 캐시된 결과값만 사용합니다.
5. **자동 분석은 규칙 기반 초안**입니다. 제조사/모델/프로토콜 추정과 레지스터 주소가 틀릴 수 있으며, 관리자 승인 전에는 수집에 사용되지 않습니다.
6. ZIP 내부의 모든 형식을 완벽히 재귀 분석하지는 않습니다(지원 형식만 추출).

## 3. 원격제어

1. **실장비 제어 검증 없음**: 시뮬레이터 코일 쓰기/피드백으로만 검증했습니다.
2. **운전 스케줄·피크제어 자동 실행 워커 없음**: 스키마와 API는 있으나, 시간 기반 자동 실행 스케줄러는 구현되지 않았습니다.
3. **보호계전·비상정지 우회 없음(의도적)**: EUMBMS는 현장 안전장치를 대체하지 않습니다.
4. **불확정 상태 자동 복구 없음(의도적)**: 통신 장애·피드백 미확인 시 자동 재전송하지 않고 현장 확인을 요구합니다.
5. **제어 대상 매핑은 수동 설정**: 자산의 `interlocks.control.tagId`/`feedback.tagId`를 관리자가 지정해야 합니다.

## 4. 알람·통보

1. **이메일·문자·푸시 발송 미연동**: `channels` 필드는 있으나 실제 발송은 인앱 알람만 동작합니다.
2. **RATE_OF_CHANGE(변화율) 조건 미구현**: 조건 값은 스키마에 있으나 평가 로직이 없습니다.
3. **알람 억제/에스컬레이션 정책 없음**: 반복 알람 합산과 자동 복구만 지원합니다.

## 5. 검침·요금

1. **요금은 추정치**: 요금표 설정에 따른 계산이며, 한전 고지서·관리비 정산과의 일치를 보장하지 않습니다.
2. **계량기별 상세 검침 주기/프로파일 없음**: 누적값 기반 월별 차분을 사용합니다.
3. **탄소배출계수 고정(0.4781 kgCO₂e/kWh 기본)**: 국가/연도별 계수 변동을 자동 반영하지 않습니다.
4. **관리비 연계 미구현**: 외부 관리비 시스템 API 연동은 없습니다.

## 6. 성능·확장

1. **성능 목표는 설계 목표이며 부하시험 미실시**: 게이트웨이당 100대, 사업장당 10,000태그, 중앙 100,000태그는 목표치입니다. 실제 처리량은 폴링 주기·장비·네트워크에 따라 달라집니다.
2. **태그 수집은 순차 처리**: 장치별 태그를 순서대로 읽습니다. 대규모 현장에서는 드라이버 레벨 배치 최적화가 필요합니다.
3. **TimescaleDB는 선택 사항**: docker-compose에 TimescaleDB 이미지를 사용하지만, hypertable 변환은 자동 적용되지 않습니다(`scripts/timescale-setup.sql` 수동 실행).
4. **수평 확장 미지원**: 서버 내장 수집기는 단일 프로세스 기준입니다. 다중 인스턴스 운영 시 게이트웨이 기반 수집을 권장합니다.

## 7. 보안·운영

1. **PostgreSQL RLS 미적용**: 테넌트 격리는 애플리케이션 계층의 `tenant_id` 조건으로 수행합니다. DB 직접 접근자는 모든 테넌트를 볼 수 있으므로 DB 계정을 최소 권한으로 제한해야 합니다.
2. **라이선스 한도는 기록 관리**: 최대 장치/태그 초과 시 자동 차단(enforcement)은 구현되지 않았습니다.
3. **MFA/SSO 미지원**: 이메일·비밀번호 로그인만 지원합니다.
4. **감사로그 위변조 방지(해시 체인) 없음**: append-only 운영 정책과 DB 권한으로 보호해야 합니다.
5. **외부 보안 감사 미실시**.
6. **Windows 서비스 등록은 NSSM 등 외부 도구 필요**: 설치 스크립트는 안내만 제공합니다.

## 8. UI/접근성

1. **다국어 미지원**: 한국어 UI만 제공합니다.
2. **CAD(DWG) 직접 편집 없음**: PDF/이미지 배경 등록과 SVG 요소 편집만 지원합니다.
3. **모바일 네이티브 앱 없음**: 반응형 웹으로 제공합니다.

## 9. 검증 환경

- 테스트는 로컬 PostgreSQL 18 + Node 24 + `next start`에서 수행했습니다.
- Docker/Windows 환경에서의 설치 스크립트는 **문서화되었으나 이 환경에서 실행 검증되지 않았습니다**(Linux 로컬 스크립트 일부만 확인).
- 실장비·현장 네트워크에서의 통신 품질·지연·패킷 손실 시험은 수행하지 않았습니다.
